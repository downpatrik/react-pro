# React PRO

Учебное приложение на React, TypeScript.

## Запуск

```bash
npm ci
npm run dev # http://localhost:5173/tasks
npm run build
npm run lint
```

## Страницы

- `/tasks` - управление задачами.
- `/register` - регистрация через учебный API на RHF с Zod и выбором ролей.
- `/subscribe` - двухшаговая подписка на `useActionState`.
- `/refs` - пять примеров `useRef`: клики, предыдущий ввод, фокус, debounce и WebSocket.
- `/login` - вход по email и паролю через учебный API.
- `/profile` - защищённый профиль с восстановлением сессии и кнопкой выхода.
- `/public` - открытая страница, доступная без авторизации.

`/register` создаёт аккаунт через `POST /auth/register`. Вместо социальных ссылок
можно выбрать роли `USER` и `ADMIN`; по умолчанию выбрана `USER`.
После регистрации можно перейти на `/login` и войти с теми же данными.
Только `/subscribe` использует учебную отправку без backend и реальной рассылки.
Рабочий адрес API - `https://api.v2.react-learning.ru`,
документация Swagger - `https://api.v2.react-learning.ru/api`.

Регистрация, вход и загрузка профиля используют RTK Query: `register` и `login`
mutation, `getMe` query. Имя из формы отправляется в поле `name`, подтверждение
пароля проверяется только в браузере. При занятом email отображается ошибка 409.
Сервер возвращает `accessToken` с префиксом `Bearer`: перед сохранением префикс
удаляется, чтобы заголовок авторизации содержал его ровно один раз.
Токен входа хранится в контексте авторизации и в `localStorage` под ключом `authToken`.
После обновления страницы профиль снова загружается через `GET /users/me`.
При выходе или ответе 401/403 на запрос профиля сессия и кеш API авторизации очищаются,
а `/profile` перенаправляет на `/login`.
