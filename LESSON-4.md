# LESSON-4 - Управление формами в React

## Запуск

```bash
npm ci
npm run dev # http://localhost:5173/register
npm run build
npm run lint
```

- `/tasks` - управление задачами.
- `/register` - регистрация с динамическими социальными ссылками.
- `/subscribe` - двухшаговое подтверждение подписки.

## Чеклист задания

- [x] Форма регистрации на React Hook Form - критерии на 4 балла.
      [UserRegistrationForm](src/features/user-register/ui/UserRegistrationForm.tsx)
      использует `useForm`. Имя пользователя, email, пароль и подтверждение
      обязательны. Проверяется корректность email, длина пароля от 6 символов
      и совпадение паролей. Ошибки отображаются рядом с соответствующими полями;
      первое невалидное поле получает фокус.
- [x] Схема Zod через `zodResolver` - критерии на 2 балла.
      [registrationSchema](src/features/user-register/model/registrationSchema.ts)
      подключена сразу при создании формы. Поэтому отдельный перенос ручной
      валидации не требуется: пункты 1 и 2 выполнены одной реализацией.
      Тип `RegistrationValues` выводится из схемы через `z.infer`.
- [x] Динамические социальные ссылки - критерии на 4 балла.
      `useFieldArray` управляет массивом объектов `{ url: string }`.
      По умолчанию есть одно пустое поле. Можно добавлять и удалять любые строки,
      в том числе последнюю; оставшиеся значения и ошибки сохраняют соответствие.
      Для React-ключей используется стабильный `field.id`.
      Каждая оставшаяся строка обязательна и валидируется как URL через `z.url`
      из Zod 4. Для регистрации без ссылок нужно удалить все строки.
- [x] Бонус: wizard на `useActionState` - критерии на 2 балла.
      [SubscriptionWizard](src/features/subscription-wizard/ui/SubscriptionWizard.tsx)
      передаёт action в `<form action={formAction}>`.
      [subscriptionAction](src/features/subscription-wizard/model/subscriptionAction.ts)
      проверяет email и возвращает состояние первого шага, подтверждения либо успеха.
      UI показывает `pending`, ошибку и успешное подтверждение.
      При возврате к первому шагу сохраняется email; его можно изменить.

## Отправка и состояния

Отправка учебная, без регистрации аккаунта на сервере и без реальной рассылки.
[registerUser](src/features/user-register/api/registerUser.ts) и action подписки
имитируют асинхронный ответ с задержкой 500 мс.

Поля и кнопки блокируются на время отправки. После ошибки регистрации введённые
значения остаются в форме, запрос можно повторить. После успеха поля регистрации
сбрасываются, включая пароль; кнопка «Заполнить снова» возвращает пустую форму.
Пароли не записываются в storage и не выводятся в консоль.

Бонус.
В wizard email контролируется локальным состоянием, чтобы автоматический сброс
формы React после action не стирал введённый адрес при ошибке или возврате назад.
Подтверждение использует email из проверенного состояния предыдущего шага.
